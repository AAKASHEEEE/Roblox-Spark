# Vignette-sourced S7 v2 full render replaces the NarratedScene visual path (v1)

The v2 redesign swaps the legacy NarratedScene visual source in the S7 full-video render for the integrated Vignette path, so the approved 69.167s voice-over is now staged with a real teacher exit/return, a real hinged door, full-body character acting, and competitor-grade cutting/movement/zoom — while keeping the approved VO bytes and timing untouched and the audio VO+event-SFX-only (no music). It adds a new S7-owned browser adapter (`window.__s7v`) that renders the real `VignetteScene` off the runVignette-solved cameras, extends `render-full.ts` with a `--visual vignette` default that runs a new bank of pixel/geometry/motion gates, adds an intra-beat `camera.subShots` feature to hit the editing-cadence targets, and produces `packages/captions/full-render-v2/` plus `COMPETITOR_ANALYSIS.md`. The v1 golden render is left byte-identical and the raw competitor media / voice MP3 stay under `.scratch/` (gitignored).

Watch for: the dense camera audit is a per-composition acceptance replayed per output frame, not an independent per-frame re-projection — it is meaningful (a blocked camera throws earlier) but framed slightly stronger than what it recomputes (confirmed). Everything else — real teacher@1.0.0 / door@1.1.0 geometry gates, full-body motion gates, approved-VO authentication and no-cut padding, music-none + 19 event SFX, v1 byte-identity, no committed competitor media — holds up (confirmed).

**Verdict**: APPROVED

## High-level view

The adapter is a genuine sibling of the stills-page module rather than a fork of NarratedScene logic: it stages the same validated beat sheet into a real `VignetteScene`, drives the runVignette-solved `ShotChoice` cameras through `poseAt` + `scene.pose(t)`, and composites the existing S7 overlay stack (VFX/emotes/world-text/ui_popup/title_card/caption_bold). It exposes the same `init/place/initCapture/encodeRange/meta` surface plus three diagnostic hooks (`teacherVisibility`/`doorState`/`jointSample`) that read real projected geometry, and it does not fabricate a teacher or door — it resolves them from the scene's own rigs/props and reports the resolved source key.

The render gates in `render-full.ts` read those real diagnostics and would fail if the teacher/door were missing or if motion were only head-turns: the teacher gate requires a projected screen-area fraction (not mere rig-presence) sourced from `teacher@1.0.0`, the door gate requires the real `door@1.1.0` grip to physically travel between closed and open with the doorway on camera and `usedRealDoorway` true, and the motion gate requires metre-scale world-space joint/root deltas per action window with conservative thresholds. None of these are trivially true.

The approved VO is authenticated by SHA-256 against `storyboard.audio.contentHash` before anything renders, decoded once, and only ever zero-padded up to the frame count — the code throws rather than cut it. The audio mix forces music `none`, asserts exactly 19 event SFX cues, and requires SFX to sit ≥6 dB under active voice. The v1 golden directory is guarded by an explicit refusal path and is untouched in the diff (its SHA-256 is unchanged).

The `camera.subShots` feature adds validated intra-beat hard cuts, threaded through `runVignette` as a `compositions[]` timeline where each sub-shot is solved as its own camera-safe shot; captions re-band only at those cuts, staying one band per composition. The competitor analysis scores v2 at ~7.4 vs v1 ~4.5–5 with per-axis backing, and the comparison sheet is built only from our own v1/v2 decoded frames plus derived numeric charts — no competitor footage, characters, UI, or logos.

### Adapter does not fabricate the teacher or door

There is no NarratedScene / `buildWorldPlan` code path in the module, and capture routes `framePng` and `encodeRange` through the same pure `drawFrame(t)`. Of note for the gates that follow: `teacherVisibility` reads `scene.sources['character:teacher']` and the actual `scene.rigs.get('teacher')`, returning the resolved source key so the gate can require `teacher@1.0.0`, with `present` gated on `actorPresent(plan, 'teacher', t)`. `doorState` finds the real door prop instance, detects the real `doorway:*:opening` node (and fails `usedRealDoorway` if a `doorway:*:fallback` exists), and derives `openAmount` from the grip's *planar travel* relative to the closed baseline rather than from the authored timeline — so the value reflects the real S4 leaf, not a fabricated one.

### Gates read real geometry and would fail on a fake

The teacher gate samples exit (p01), return (p13), and present (p14) windows, requires `sourceKey === 'teacher@1.0.0'` and `source !== 'placeholder'`, and — critically — requires `areaFrac >= 0.006`, a projected screen-area fraction, so a teacher that exists but is off-camera or a pixel speck fails. The recorded run shows all three windows meaningfully visible from `teacher@1.0.0`.

The door gate requires `usedRealDoorway`, `sourceKey === 'door@1.1.0'`, a grip planar move `> 0.05 m` (or `openAmount` delta `> 0.1`) between closed and p01-open, and the doorway on camera in both p01 and p13. A fabricated or static door fails the movement check; a fallback doorway fails `usedRealDoorway`.

The performance-motion gate is the strongest anti-head-turn guard: for 14 action windows it requires metre-scale world-space deltas of named joints/root (e.g. `p06_zapp_walk_to_button` root/hip ≥ 0.4 m, `p03_celebrate` hands/spine/root ≥ 0.2 m), and asserts a FaceTrack expression is present and `mouthNarrationDriven === false`. The recorded deltas clear the thresholds with wide margin (walk 1.08 m, prone 2.02 m, celebrate 1.75 m). The one small-threshold window (`p14_teacher_look`, ≥ 0.01 m) is explicitly documented as a deliberate head/neck re-orientation, not a walk, and the other 13 carry the full-body burden. `mouthNarrationDriven` is structurally false because the FaceTrack has no phrase/mouth driver — the mouth is only opened by S5 action FaceCues, never the VO — and the gate still exposes the raw mouth token as evidence. Determinism is checked by sampling the same actor at the same `t` twice and requiring identical texture key + blink.

The dense camera audit is the one gate whose framing outruns its mechanism. It walks every output frame, buckets it to its active composition, and requires `c.shot.accepted && c.shot.source !== 'blocked_best_effort'`, recording per-beat accepted-frame fractions. It is not a no-op — a blocked composition already threw during the pipeline solve, and `solveBeatCamera` marks a shot `accepted` only when *every* sample in its window passed — so a frame in an accepted composition is provably in a camera-safe window. But it replays precomputed per-composition acceptance rather than independently re-projecting safety per frame, so "30fps dense audit" describes the sampling grain, not a fresh computation. It does not weaken camera safety; the naming is the only concern.

### Caption face-safety spans all faces and re-bands only at hard cuts

`place()` computes occupancy from every visible rig's face+body — including the teacher — plus every visible prop and active `ui_popup` graphic, over each shot segment. A caption is held stable within one camera shot and may re-band only at a hard cut (beat boundary or sub-shot cut), so there is still one caption band per composition. `render-full.ts` then rejects any placement with `!clearOfFaces || faceOverlapPx !== 0` across all segments — the recorded run reports zero conflicts.

### subShots: validated intra-beat cuts, camera-safe per window, screen-direction preserved

The `camera.subShots` schema addition is validated: each sub-shot's recipe is registered via `use('cameraRecipes', ...)`, its subject/secondary must be beat entities (secondary distinct from subject), and its `from` must be strictly inside the beat and strictly increasing — the validator threads `prevFrom` starting at `b.start` and rejects any cut `<= prevFrom` or `>= b.end`. This is purely additive, so the pre-existing camera validation for beats without sub-shots is unchanged (the runtime integration test still loads and stages the free-coins fixture, which now carries sub-shots, and the director test's generated sheets still validate).

`runVignette` now emits a `compositions[]` timeline: the beat's own camera is composition 0, then each sub-shot, each solved as its own `ShotChoice` over just its `[cStart, cEnd)` window with `keyTimes` filtered to that window. Screen direction threads sub-shot → sub-shot inside the beat and resets on an axis change (previous subject is neither this composition's subject nor secondary), exactly as a beat cut does, so an intra-beat cut cannot introduce a false 180° reversal. The axis carried to the *next* beat is deliberately the one from composition 0 (`carrySd`), not a transient sub-shot subject. A new beat-level reset was also added for a hero entering the scene (`placementKind === 'enter'`), which is consistent with the existing exit-reset rationale. The result is coherent: 41 compositions, median 1.6 s, 0 repeated identical Zapp/Kira singles, translation 0.456, zoom 0.324 — all inside the metric acceptance ranges.

### Approved VO is authenticated and never cut

Before any render work, the voice bytes are hashed and compared to `sb.audio.contentHash` (throws on mismatch), the container is checked, and the decoded duration is compared to the approved `durationSeconds` within 0.05 s. The VO is decoded once to mono 48 kHz float PCM and then only zero-padded to the frame-count sample length; if the voice were *longer* than the frame budget the code throws rather than truncate (`refusing to cut voice`). There is no stretch or resample of the VO anywhere in the path. This preservation is identical across both visual modes.

### Audio stays VO + event SFX, music none

The mix forces `music !== 'none'` to fail, requires every planned SFX cue to mix successfully, asserts the beat-sheet's music was ignored as `music_added_in_editing`, requires exactly 19 event SFX cues, and requires SFX to sit ≥ 6 dB under active voice (with a ≥ 6 dB floor on the requirement itself). LUFS/true-peak are checked against the S7 policy. The recorded report confirms `music: none`, 19 cues, and the speech-margin gate.

### v1 golden untouched; deliverables committed, intermediates ignored, no competitor media

`render-full.ts` explicitly refuses any `--out` resolving to `packages/captions/full-render/` and requires the output dir to be inside the repo. The diff touches no file under `full-render/`, and the v1 MP4 SHA-256 is unchanged (`6317…afe28`). The v2 directory commits the mp4, `verification.json`, the 7 named frame PNGs, and `comparison-sheet.jpg`; the four derived intermediates (`audio-report.json`, `caption-placements.json`, `mix.wav`, `probe.json`) are gitignored with a comment clarifying the deliverables are intentionally *not* ignored. No `.scratch/`, no `*.mp3`, and no competitor MP4 is tracked. The comparison-sheet builder sources frames only from the committed v1/v2 MP4s and renders competitor influence solely as derived numeric charts — no competitor footage, characters, UI, logos, or trade dress. `COMPETITOR_ANALYSIS.md` scores v2 at ~7.4 vs v1 ~4.5–5 with per-axis backing tied to the verified gate outputs.

### Unrelated changes

None. The `ffmpeg-static` / `ffprobe-static` devDependencies and the `package-lock.json` growth serve the render/analysis tooling this PR introduces.
